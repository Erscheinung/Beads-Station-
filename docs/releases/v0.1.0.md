# Beads Station v0.1.0 — early preview

Beads Station v0.1.0 is an early, Apple Silicon macOS preview of the terminal-first Developer workspace. It is intentionally a `0.x` release: important workflows remain incomplete and compatibility may change between minor releases.

## Install

1. Download `Beads.Station_0.1.0_aarch64.dmg`.
2. Verify its SHA-256 value against the attached `.sha256` file.
3. Open the DMG and drag **Beads Station** to **Applications**.
4. The build is ad-hoc signed, not Apple Developer ID signed or notarized. If macOS blocks it, right-click the app and choose **Open**, or allow it once in **System Settings → Privacy & Security**.
5. Install `bd` for ticket features. Install and authenticate `codex`, `claude`, or `nvim` only for integrations you want to use.

If an older build shows repeated `Too many open files (os error 24)` messages, quit every old Beads Station instance and replace it with this release. The rebuilt v0.1.0 package raises the native file limit before starting subprocesses.

## What works

- Explicit project discovery and workspace opening without opening every discovered repository.
- Local terminals, tabs, split right/down, close, unsplit-to-tabs, and fullscreen.
- Configurable pane focus on `Command+Option+Arrow`, pane resize on `Command+Option+Shift+Arrow`, and fullscreen on `Command+Shift+Enter` by default. All nine pane actions can be changed or cleared in Settings.
- Independent Developer and Designer themes, including the Fahrenheit Developer theme.
- Persisted interface scale from 80–120%, comfortable/compact density, and reset.
- Local `bd` ticket lists, boards, details, and the empty-gate compatibility repair.
- Explicit local Claude/Codex chat entry points when the corresponding CLI is installed and authenticated.
- Native startup protection against the old packaged-build file-descriptor exhaustion storm.
- Designer graph cards expand to fit wrapped titles, preserve 24px spacing, and align connectors to each card's actual center. This is visual prototype behavior, not a functional Designer workflow.

## What does not work yet

- **Designer is a prototype.** It does not yet provide a dependable end-to-end request → agent run → artifact preview → revision → approval workflow. Do not use it for production approvals.
- Closing the app ends its local PTYs and provider processes. Saved layouts are not durable process attachment.
- Provider authentication and real paid-provider runs were not exercised for this release. Availability depends on separately installed and authenticated CLIs.
- GitHub/Jira synchronization, durable conductor leases, artifact review, auto-update, signing, and notarization are not complete.
- The DMG is Apple Silicon-only. Intel macOS, Windows, and Linux packages are not included.
- The deferred Svelte evaluation is tracked as `Code-1dh`; no migration has been performed or promised.

## What to test

- Install from the DMG and confirm first launch succeeds without repeated file-descriptor errors.
- Open a repository by exact path, switch away and back, and confirm only explicitly opened workspaces restore.
- Type and paste Unicode in a terminal; launch your normal Neovim/LazyVim setup and inspect Fahrenheit colors.
- Split panes, move focus with `Command+Option+Arrow`, resize with `Command+Option+Shift+Arrow`, and toggle fullscreen with `Command+Shift+Enter`.
- Rebind or clear those actions in Settings, restart, and confirm persistence.
- Change interface scale and density, reset them, and confirm terminal input remains responsive.
- Open repositories both with and without a local Beads database and verify the ticket UI fails gracefully.
- Browse Designer as a prototype and report layout/readability issues, but do not expect its execution or approval actions to complete a real workflow.
- In the Designer bead graph, check that long titles remain inside their cards, adjacent cards keep their spacing, and connector lines meet the vertical center of each card.

## Verification recorded for this build

- Vitest: 175/175.
- Playwright Chromium/mock: 75/75.
- Rust: 103/103 (including the focused gate parser coverage).
- Production frontend build: passed.
- Native Tauri release build: produced `.app` and `.dmg`.
- Rebuilt packaged app: current repository loaded 24 issues in about 1.1 seconds with Fahrenheit restored and no `os error 24` notifications after the old runaway build was removed; `Command+Shift+Enter` entered fullscreen and displayed the corrected shortcut hint.

Browser/mock checks do not prove WKWebView, actual PTYs, CLI authentication, or durable process behavior. The native checks above cover launch, project loading, theme restoration, and absence of the reported spawn storm; the remaining items are explicit test requests.

## Future release direction

- **0.1.x:** packaging and native stability fixes, clearer diagnostics, signing/notarization preparation, and fixes found during preview testing.
- **0.2.x:** a functional Designer request/artifact preview/revision/approval loop with approvals bound to exact run revisions.
- **0.3.x:** durable runtime ownership, reconnect/reconciliation, and stronger cancellation semantics across app restarts.
- **Later 0.x:** external issue/PR integrations, release automation, measured performance work, and evidence-based evaluation of a possible Svelte migration.

These are directional plans, not delivery promises. Release contents are determined by verified behavior at each tag.

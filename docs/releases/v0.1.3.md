# Beads Station v0.1.3 — Designer artifact-review preview

Beads Station v0.1.3 is an Apple Silicon macOS prerelease. It includes the closed local Designer artifact/revision review slice, but it is **not** a completed Designer release. The remaining B-workstream tickets are deliberately listed below and will be closed only in subsequent releases when their acceptance evidence exists.

## Install or upgrade

1. Download `Beads.Station_0.1.3_aarch64.dmg` and its `.sha256` file.
2. Verify it with `shasum -a 256 -c Beads.Station_0.1.3_aarch64.dmg.sha256`.
3. Open the DMG and drag **Beads Station** to **Applications**, replacing the previous copy if prompted.
4. This package is ad-hoc signed and not notarized. If macOS blocks it, right-click the app, choose **Open**, or allow it once in **System Settings → Privacy & Security**.

## What is new

- `Code-am5.1` is closed: a Designer native run retains its exact workspace/ticket/attempt identity across navigation and UI reload; unknown state never silently relaunches work.
- `Code-am5.2` is closed: Designer can capture and recapture bounded immutable UTF-8 artifact revisions, preview safe text/diffs, retain revision feedback, and approve only the exact current run/revision locally. Stale, mutated, binary, oversized, symlinked, escaped, or incomplete captures fail closed.
- This release includes the current Designer graph screenshot as a visual placeholder, not evidence of a completed real-provider journey.

## Still open — not claimed by this release

- `Code-am5` remains in progress; the parent Designer execution slice is not closed.
- B1 / `Code-yfb`: durable conductor attempt leases and bounded execution policy are open.
- B2: configured harness/provider profiles and immutable per-run configuration are not complete.
- B3: the local artifact contract is closed, but the packaged WKWebView, real-provider request → run → revision → approval journey is not yet accepted.
- B4/B5: configuration/connections and optional intake pulses remain open.
- B6: packaged release acceptance across supported profiles remains open.

Do not use Designer approval for production publication, merge, or provider authorization. Approval is local only and does not publish, merge, post, or start a model. Provider authentication and paid provider flows were not exercised for this release.

## Hands-on checks requested

- Open a Designer request, use a local fixture artifact, capture it, inspect a text/diff preview, request a revision, and confirm stale/mutated content cannot be approved.
- Confirm an unavailable or unconfigured provider is reported without automatic launch or credential inspection.
- In the packaged app, exercise the complete explicit request → provider run → artifact → revision → approval journey only with authorized provider credentials; record the outcome before closing B3/B6.
- Continue the normal Developer workspace checks: native Browse, terminal Unicode/IME/Neovim, workspace/tab ordering, Beads initialization, and recipe import/export/replay.

## Direction

The next releases will close the remaining B tickets only as their acceptance gates are met: first durable run ownership and profile configuration, then real packaged Designer journeys and B6 release acceptance. This is a preview release, not a claim that the complete 0.2 Designer roadmap has shipped.

# Beads Station v0.1.6

Apple Silicon macOS preview. This release fixes the terminal's hidden bottom rows and several focus, restart and shortcut problems, and adds: a list of waiting panes, macOS notifications, exact "waiting for you" signals and exact session resume for Claude Code and Codex, a browser pane, self-installing updates, an optional mode that keeps terminals running after the app quits, and a Designer session that can take a ticket from start to approval.

Nothing in this release has been run in the packaged app yet; see the checklist.

## Install or upgrade

Download `Beads.Station_0.1.6_aarch64.dmg` and its `.sha256` from this release.
Run `shasum -a 256 -c Beads.Station_0.1.6_aarch64.dmg.sha256`, quit the old app after saving work, open the DMG, and drag Beads Station to Applications.
The app is ad-hoc signed, not Developer ID signed or notarized. If macOS blocks launch, right-click the app and choose Open, or allow it in Privacy & Security.
From 0.1.6 onward, Settings → About → Install can do this for you.

## Changes

### Terminal and daily use

- **Bottom rows no longer hide under the status bar.** In the Terminal only view the terminal area could grow but never shrink. After leaving fullscreen, after the tab strip appeared, or after making the window smaller, the last rows (the Claude Code or Codex prompt, the shell cursor) sat below the visible area until the next fullscreen round trip.
- **You can type straight away.** Switching terminal tabs by click or shortcut, moving between panes, opening a new tab, splitting, and entering fullscreen put the cursor in the shell. To reach pane commands from a shell, use `Cmd+P`.
- **A plain shell restarts by itself.** After quitting and reopening, a pane that only had a shell starts a new one without asking. A pane that had Claude Code or Codex running still shows **Start shell and resume**.
- **Exact resume.** That resume now reopens the conversation the pane actually had, not the latest one in the folder, when the pane knows it: Codex's session is read from the running process, Claude Code's from a hook (below). Two agent panes in one folder no longer resume the same conversation.
- **Keep terminals running when the app quits (optional, off by default).** Settings → Sessions. With it on, new shells live in a small background process instead of the app. Quitting, a crash or an update leaves them running with whatever is inside (Claude Code, Codex, a dev server), and the next launch reattaches each pane with its recent output. They do not survive logging out or restarting the Mac; then a pane falls back to its saved screen and the resume offer. Closing a pane or workspace still stops its shell. The background process exits by itself when it holds no shells.
- **Copy on select.** Finishing a mouse selection copies it (Settings → Terminal). `Cmd+C` copies the selection directly. Hold Option while dragging to select text inside Claude Code, Codex or Neovim, which capture the mouse.
- **Text size shortcuts.** `Cmd +`, `Cmd -` and `Cmd 0` change the terminal text size; all three can be rebound.
- **Shortcuts with Tab, and Control keys back in the shell.** The recorder accepts Tab chords such as `Control+Tab`. On macOS, Control with a single key (Ctrl-K, Ctrl-R, Ctrl-W, Ctrl-Q) always reaches the shell; Ctrl-W and Ctrl-Q used to open the quit dialog. `Command+Tab`, `Command+Space`, `` Command+` `` and `Command+H` belong to macOS and cannot be recorded by any app.
- **Terminal fills its pane on first show.** A terminal whose pane never changed size after it appeared could stay at 80x24.
- **Browser pane.** `Cmd+Shift+L`, the Browser button, or the command palette opens a web page beside the terminal; its address is restored with the layout. A local link printed in a terminal (a dev server URL) opens there when clicked. The pane is a sandboxed frame, so sites that refuse to be framed (most sign-in pages) show blank: the **Window** button opens them in a separate window that keeps its own cookies between launches. That window is not Safari's or Chrome's profile.
- **What's new.** The first launch after an update lists the changes once. A first install shows nothing.
- **Open a folder from Finder.** Right-click a folder → Open With → Beads Station, drop a folder on the Dock icon, or run `open -a "Beads Station" <folder>`.

### Notifications

- **Waiting panes.** `Cmd+I`, or the **Waiting N** button that appears in the toolbar, lists every pane that is waiting, newest first, with where it is. Click one to jump to it, or dismiss it.
- **macOS notifications.** Settings → Notifications can also post to Notification Center while the app is in the background. macOS asks for permission when you turn it on.
- **Exact signals from Claude Code.** Claude Code can tell a pane the moment it needs permission, is waiting, or has finished, instead of the app guessing from a quiet terminal. Sessions the app starts (Designer session, resume) do this automatically. For `claude` you type yourself, Settings → Notifications → **Add hooks** adds three hooks to `~/.claude/settings.json` (a backup is written beside it; **Remove hooks** takes them out). The hooks do nothing outside Beads Station. A pane that reports for itself no longer also gets the "went quiet" guess.
- **Codex** started by the app reports a finished turn itself. For `codex` you type yourself, start it with `-c tui.notifications=true`.

### Updates

- **Install from the app.** Settings → About → **Install vX** downloads the release, checks it against its published SHA-256, checks that the app inside is Beads Station at that version with an intact signature, and places it next to the installed app. **Restart to update** then asks before closing your sessions, replaces the app and opens the new version. Until you restart, nothing is replaced. A release without a published checksum is not installed automatically; **Download only** still works.

### Designer

- **Session.** A new Session item runs the real `claude` or `codex` CLI (or a plain shell) in the workspace, with your own login, next to a Changes panel that lists new, edited and removed files with line counts and a diff per file. Nothing starts until you choose what to run. From a request, **Open in a live session** carries the ticket over.
- **Finish a ticket in the session.** With a ticket in the session, **Capture for review** freezes the changed files, **Approve** approves that exact capture, and **Close ticket** closes it. **Request changes** puts your note at the agent's prompt and starts a new attempt, so the earlier capture can no longer be approved.
- **Opus conductor.** The request panel's Opus conductor is no longer a placeholder: it runs Claude Code through the Opus/Sonnet adaptive orchestrator (Opus plans, Sonnet workers implement, Haiku reads). It is available when that skill and its `sonnet-worker` agent are installed in the workspace's `.claude/` or in `~/.claude/` (its `setup.sh` installs both).
- **Workers are visible.** A run now says when the primary agent starts a worker, waits for it, and what the worker reported. For Codex orchestrator runs a Workers section lets you open each worker and read what it has done; for the Opus conductor the worker's lines appear in the run, marked "Worker".
- **Agents** shows the agents list instead of a placeholder.
- **Tracker files stay out of artifacts.** A capture no longer includes `.beads/` changes.

## Known limits

- Nothing here has been run in the packaged app. Browser-harness and backend tests do not prove WKWebView layout, clipboard access, Finder integration, Notification Center, key delivery, or the update swap on a real installation.
- Keep terminals running is off by default for that reason. It was verified against real shells both in tests and as a real detached process started from the built binary, but not from inside the installed app. If the background process cannot be reached, a pane gets an ordinary shell.
- The update swap was tested on stand-in folders with a stand-in process, never on an installed copy. If the app is not running from a writable `.app` bundle, Install says so and Download only remains.
- The Opus conductor was not run against a provider in this release; its command line and availability rules are tested, its behaviour is that of the skill.
- "Copy and paste is wonky" was reported without detail. Claude Code and Codex capture the mouse, which is the likely cause; Option-drag selects there. If it still misbehaves, note the direction and the program in the pane.
- Repeated transcript text while scrolling: Claude Code 2.1 and Codex 0.162 both draw in the terminal's alternate screen, where there is no scrollback for a reprint to pile up in, so the original cause no longer applies to them. Not otherwise changed.
- The browser pane cannot show sites that forbid framing; use Window. Back and forward inside the pane are the page's own.
- Claude Code's exact session id needs the hooks. Without them a pane still resumes the latest conversation in the folder.
- A restarted plain shell starts empty unless Keep terminals running is on.
- "New Beads here" from Finder is not built. Memory profiling against cmux is deferred.
- Apple Silicon only.

## Hands-on checklist

- Install over 0.1.5: "What's new" appears once. Settings and shortcuts are kept.
- Terminal only view: start Claude Code, enter and leave fullscreen, make the window shorter. The prompt line stays visible each time.
- Switch terminal tabs with the mouse and with the shortcut, and toggle fullscreen: typing lands in the shell. `Cmd+P` then `v` still splits.
- In a shell: Ctrl-K, Ctrl-R and Ctrl-W act on the command line; `Cmd+W` asks before closing.
- Settings → Keyboard shortcuts: record `Control+Tab` and `Control+Shift+Tab` for next and previous terminal tab.
- Select text in a shell and paste it into another app. In Claude Code, Option-drag to select. `Cmd+V` into a shell from another app.
- `Cmd +`, `Cmd -`, `Cmd 0` change and reset the terminal text size.
- Split a terminal, run `sleep 6; printf '\a'` in one pane, click the other, then press `Cmd+I`: the pane is listed; clicking it jumps there.
- Settings → Notifications → macOS notifications: allow the prompt, switch to another app, let a pane finish: a notification appears.
- Settings → Notifications → Add hooks. In a pane, start `claude`, give it a task, switch tabs: the tab is marked the moment it finishes, with "Claude Code: Finished, waiting for you". Quit and reopen: the pane offers to resume, and the command shown contains `--resume` and an id. Remove hooks and check `~/.claude/settings.json` is as it was.
- Start `codex` in a pane, quit and reopen: the resume command contains that session's id.
- `Cmd+Shift+L`: type `localhost:<port>` of a running dev server; the page shows. Click a `http://localhost:…` link in terminal output: it opens in the pane. Open a site that shows blank with Window.
- Settings → Sessions → Keep terminals running. Open a new terminal tab, run `export MARK=1; top`, quit the app, reopen: `top` is still running in that pane, and after quitting it `echo $MARK` prints 1. Close the pane: `pgrep -f pty-host` shows nothing about 20 seconds after the last kept shell is gone.
- Finder: Open With → Beads Station on a folder while the app is running, and again while it is closed.
- Designer → Session: Changes lists the workspace's changes before anything starts. Start Claude Code, ask for a small edit, watch the file appear.
- Designer → a request → Open in a live session → Start Claude Code on it → after the edit, Capture for review → Approve → Close ticket.
- Designer → a request: with the orchestrator skill installed, choose Opus conductor and Start work; "Delegated to sonnet-worker" and "Worker:" lines appear.
- When 0.1.7 exists: Settings → About → Install, then Restart to update.

## Verification

- Vitest 293/293. Playwright Chromium with mock IPC 99/99. Rust 149 passed, 2 opt-in tests ignored; one full run failed two older tests that share global run state with each other and passed on three consecutive reruns. Production frontend build, `cargo check` and `git diff --check` passed.
- The clipping regression test fails on the previous layout and passes with the fix.
- Terminal host: tests start real shells, drop the client, reconnect, and check the same process id, replayed history and kept environment. The built binary was also run in host mode as a detached process and driven over its socket through the same sequence, including exiting by itself when idle.
- Claude Code hooks: checked by starting the real Claude Code in a pseudo-terminal with the hook settings and no prompt; the session id arrived in the terminal stream. That is how it was found that a hook has no controlling terminal and must be given the terminal device path. Codex was started the same way to confirm it accepts the notification settings. No model turn was sent in either.
- Update swap: the real swap program was run against stand-in app folders and a stand-in process, for the normal case and for an app that never quits.
- No provider run and no packaged-app check were made.
